# EcoPoints: gotchas

1. **Supabase grants everything in `public` to anon/authenticated by default.** The migration revokes it all at the end and re-grants exactly what's needed. Any new table or function needs the same treatment: enable RLS, add a SELECT policy if clients read it, and `revoke … from public, anon, authenticated` on new functions, then grant only what's intended. Re-run `supabase/tests/ecopoints_checks.sql` after any schema change.
2. **Function bodies use `set search_path = ''`.** Fully qualify everything (`public.classes`, `auth.uid()`), or the function fails at runtime, not at creation.
3. **Next.js 16:** `middleware.ts` is now `src/proxy.ts`, and `params`/`searchParams`/`cookies()` are async. The scaffold's `cacheComponents` / `partialPrefetching` are deliberately **off**: every page is live data and they'd force Suspense boundaries everywhere. Bundled docs are in `node_modules/next/dist/docs/`.
4. **PINs are 6 digits**, not 4: Supabase Auth's minimum password length is 6.
5. **Monitor login addresses** are `ecopoints-m-<class uuid>@<MONITOR_EMAIL_DOMAIN>`. No email is ever sent. Changing `MONITOR_EMAIL_DOMAIN` after PINs exist breaks those logins (reset each PIN to recreate).
6. **Checklist edits are forward-only.** An item's code, type (count / yes-no) and who answers are fixed once created, because past answers depend on them. Label, points, SDGs, order and on/off can change; past points don't.
7. **Closing a month is permanent.** Void or adjust first. The database refuses any points row dated in a closed month.
8. **"Today" comes from the database** in the school's time zone (`schools.timezone`, default Asia/Dubai), never from the server clock.
9. **Login rate limiting:** monitor/teacher sign-in goes through a server action, so Supabase's per-IP auth limits see Vercel's IP, not the student's. Low risk for a pilot (a class login only reaches eco points), but if this goes wider, add attempt throttling or move sign-in to the browser client.
10. **Server-action success messages vanish** when the action changes what the page shows (e.g. closing a month replaces the button with the result). That's expected.
11. **`NEXT_PUBLIC_SCHOOL_SLUG` is the school's short code (`school` from seed.sql), not its name.** The name ("Credence High School") lives in the database and is changed in Teacher → Settings or with `update public.schools set name = … where slug = 'school'`. The code must match `^[a-z0-9-]{2,40}$`.
12. **Windows + Node scripts:** don't call `process.exit()` right after closing a readline interface. Node can crash with `Assertion failed: !(handle->flags & UV_HANDLE_CLOSING)`. Set `process.exitCode` and return instead (as `scripts/create-teacher.mjs` does).
13. **AI counts are approximate.** Vision models miscount crumpled or overlapping items. That's why a mismatch is a *flag for review*, never an automatic penalty, and why the pilot compares AI counts against hand counts before any accuracy figure is quoted.
14. **Gemini free tier vs paid tier:** free-tier prompts and photos may be used by Google to improve its products and seen by human reviewers. Use a paid-tier key (billing linked) for anything from the school. Develop with staged photos only on the free tier.
15. **Model IDs change.** `GEMINI_MODEL` / `ANTHROPIC_MODEL` are environment settings so a renamed or retired model is a settings change, not a code change. If AI checks start failing with a 404, check the model ID first. Default is `gemini-3.5-flash-lite` (small, cheapest); `GEMINI_FALLBACK_MODEL` (e.g. `gemini-3.8-flash`) is tried once automatically if the main model fails for any reason other than a bad key. Each model has its own usage limits, so this is the competition-day safety net.
16. **Photo upload size:** server actions accept 1 MB by default; `next.config.ts` raises it to 3 MB. Photos are shrunk on the device to ≤ 1288 px JPEG first (usually under 0.5 MB). Don't remove the shrink step.
17. **The bin check needs today's class check first** (it uses that day's "students present" and plastic-free count). The room photo needs the peer check first. Both are one per class per day; a teacher void allows a retake.
18. **`public_school` was redefined in the AI migration** (it now also returns AI settings). If you edit it again, edit the newest definition.
19. **AI errors are shown on screen as they are** (e.g. "API key not valid", "Resource has been exhausted", "AI isn't set up"). Fine for a prototype; tone it down before real users. Changing `.env.local` needs `npm run dev` restarted to take effect.
20. **Run `npm install` after pulling the 4 Nov UI update.** Fonts (`@fontsource-variable/big-shoulders-display`, `@fontsource-variable/atkinson-hyperlegible-next`) and icons (`@phosphor-icons/react`) are now packages. Without it the build fails with "Module not found".
21. **Icons: import only from `@/components/icons`.** It imports each icon file from Phosphor's `/dist/ssr/` build, which works in server and client components and keeps bundles small. Importing from `@phosphor-icons/react` directly in a server component fails (it uses React context). Need a new icon? Add one line to `icons.tsx`.
22. **Team colours come from the class name** (`teamColor` in `ui.tsx`: (grade − 1) × 4 + section letter, over 8 colours). 7A–7D and 8A–8D all differ; with more than 4 sections or more grades, colours repeat. That's fine: the class code is always printed on the tile.
23. **Don't resize buttons or inputs with extra utilities** (e.g. `buttonClass("primary", "py-1 text-xs")`). Two Tailwind utilities for the same property resolve by CSS order, not class order, so the result is unpredictable. Add a variant in `ui.tsx` instead.
24. **The monitor login is radio tiles (`name="class_id"`), not a `<select>`.** Tests pick a class with `getByRole("radio", { name: "7A", exact: true })`.
25. **Demo data is fake and must be removed before the real pilot.** `supabase/seed-demo-month.sql` also sets the school's points start date (to make a measuring week). `supabase/seed-demo-month-undo.sql` deletes **all** activity (class checks, peer checks, AI checks, points, challenges, closed months), not only the demo rows, and clears the points start date. Classes, PINs, teachers and the checklist stay. If no class has a PIN yet, demo records are filed under the first teacher's account.
26. **Run the rewards migration after the AI one**, then `supabase/tests/rewards_checks.sql`. The migration fills in default badges, shop items and 11 eco challenges for every existing school; `seed.sql` does the same for new installs.
27. **QR codes contain the site's web address.** Print posters from the live site, or set `NEXT_PUBLIC_SITE_URL` (Vercel → Settings → Environment Variables) to it. Posters printed from `localhost` won't open on tablets; the print page warns about this. Changing the address later means reprinting.
28. **Gardens belong to classes, not students** (no student accounts by design). The brief said "each student's garden"; per-student gardens would need student logins and storing student data.
29. **Spending never lowers the score.** Since the leaves migration the garden is bought with leaves, not points. Leaves = everything earned − everything spent. If a teacher voids a record after a class has spent its leaves, the class can owe leaves; screens show 0 and it simply can't buy until it earns more. That's intended.
30. **Instant QR challenges are honour-based.** They only open by scanning (the challenge list doesn't link to them), are once a day, worth 2 points, and every claim is listed for the teacher, who can void it. A photo of a QR code can still be scanned elsewhere, so keep their points small.
31. **Badge rewards are given once per badge, ever**, the first time a class reaches it in any month. Lowering a threshold can hand out rewards straight away (on the class's next garden visit). Badges themselves restart every calendar month.
32. **`class_challenges` ≠ `eco_challenges`.** The first is the AI-drafted weekly challenge sentence; the second is the QR challenges. Don't merge them.
33. **After a server action that removes the thing you clicked** (approving a write-up removes it from the queue), its success message disappears with it (see 10). Tests wait for the item to leave instead.
34. **Run the leaves migration after the rewards one** (`20261105100000_leaves.sql` needs `20261105000000_rewards.sql`), then `supabase/tests/rewards_checks.sql`. The test now needs both and says so if leaves are missing. It switches shop prices to leaves once per school (the `leaf_rates` row is the marker), so re-running `app.seed_leaves` is safe.
35. **Leaf rates are counted live and backwards.** Class-check, peer-check and photo leaves are counted from the records each time, so changing a rate in `leaf_rates` re-prices every past record (a class could suddenly owe leaves). Set rates before the pilot and leave them. There is deliberately no screen for them.
36. **Voiding takes leaves back too; flags don't.** Voiding a class check, peer check, AI photo or approved challenge removes its leaves. A flagged AI check keeps its leaves (flags are for review, never penalties).
37. **Badge leaves are kept** once handed out, even if the month's points later drop below the badge (e.g. after a void). Lowering a badge target can hand out leaves straight away, for every month the class already passed the new target.
38. **The header leaves count is read-only on purpose.** `my_leaves` counts badge leaves that haven't been handed out yet instead of handing them out; otherwise the layout could hand them out first and the garden page would never show "you won leaves". Handing out happens in `my_garden` and `garden_buy`.
39. **Monitor actions revalidate `/monitor` as a layout** (`revalidatePath("/monitor", "layout")`) so the header leaves update after a class check, photo or challenge. The garden page doesn't revalidate (the page would remount and lose the celebration); it updates the header with a browser event (`announceLeaves` in `leaf-counter.tsx`).
40. **`teacher_challenges` and `upsert_eco_challenge` were dropped and recreated** by the leaves migration (they gained `leaves`). If you edit them again, edit the leaves migration's definitions.
